# LabelCheck

A browser-only prototype that helps a TTB compliance agent check an alcohol label image against its COLA application text. Built as a take-home assessment for the Treasury IT Specialist (AI) role.

The full requirements, decisions and the reasoning behind them live in the design doc: "Label Verification App: Requirements and Decisions". Read it before changing any decision below. If a rule here conflicts with a request, stop and ask.

## Core idea

AI reads, code judges, the agent decides.

- OCR (tesseract.js) reads the label and returns words with positions and confidence.
- Plain, auditable JavaScript rules compare what was read with the application text.
- A human makes every final decision. The app never approves a label on its own.

## Non-negotiable rules

1. **Never auto-approve.** Every label ends with an agent decision. No "confirm all" control, anywhere.
2. **Browser-only, no outside calls at runtime.** No backend, no server functions, no analytics, no cookies, no fetch to any other origin. The OCR worker, WASM core and language data are served from this app's own origin (`public/ocr/`) through `workerPath`, `corePath` and `langPath`. Never load anything from a CDN. This includes fonts: self-host them, never use a Google Fonts link.
3. **Content Security Policy.** Ship a strict policy (`default-src 'self'`, `connect-src 'self'`, `worker-src 'self' blob:`, and only the WASM allowance OCR needs). Test the deployed site with it on.
4. **Nothing sensitive is stored.** Label images and application text stay in memory and disappear on "Next label" or reload. The only thing written to localStorage is the text size preference, wrapped in try/catch.
5. **The government warning is checked exactly.** Compare word for word against the statutory text (27 CFR 16.21) after normalizing only whitespace and line breaks. "GOVERNMENT WARNING:" must be all caps. The wording check gives three results (Wording, Title bold, Legibility). Boldness is an estimate from stroke thickness inside the warning; it can only make a result worse, never better, and is not judged on very small letters. Legibility, contrast and type size cannot be read from OCR and are always left to the agent to confirm by eye.
6. **Fuzzy matching only where judgment applies.** Brand name tolerates case, punctuation and apostrophe differences (STONE'S THROW versus Stone's Throw is a match). Bottler name and address use a looser fuzzy match and lean toward Needs Review. Class and type use a normalized text match. Never use fuzzy matching on the warning, ABV numbers or net contents numbers.
7. **Uncertain means Needs Review, never a pass.** Low OCR confidence, a field not found, or more than one candidate gives Needs Review with a plain reason shown to the agent.
8. **Static hosting only.** No Netlify Functions, Forms, Identity or Edge. Hosting config lives in `netlify.toml` and `public/_headers` only, so moving to Azure Static Web Apps means porting two files.
9. **Field-driven engine.** Each field is one config entry (id, label, parsing hints, comparator, rule sentence, required or conditional). The UI renders from that config. Adding or removing a field must not need a redesign.
10. **Speed target.** Reading plus checking within about 5 seconds on an ordinary office PC. OCR starts the moment the image arrives. Comparison runs instantly when the text is pasted. Record real timings in the README.
11. **Accessible by default.** Real buttons and labels, full keyboard operation, WCAG AA contrast, status never shown by color alone (symbol plus border style), and a text size control that works in compact and full modes.

## Scope

In: seven fields (brand name, class/type, alcohol content, net contents, bottler name and address, country of origin for imports, government warning), one label image per application, distilled spirits rules, single-label flow, compact and full review modes, drafted notes with a Copy button.

Out for now: COLA integration, batch processing (deferred stretch goal), multiple images per application, beer and wine rules, any LLM, skewed or glare-affected images (documented limitation).

Best-effort fields: bottler name and address, and country of origin. Say so in the README.

## Stack

Vite, React in JSX (not TypeScript), tesseract.js, Vitest. Fuzzy matching uses our own short edit-distance code in `src/engine/text.js`, not a library. Deployed as static files to Netlify at `labelcheck-grtwrx.netlify.app`.

## Suggested layout

```
src/engine/    parse, locate, rules, triage (pure functions, no DOM)
src/ocr/       worker wrapper, image preparation, timing
src/ui/        intake, review, decision and notes
public/ocr/    self-hosted OCR engine and language files
scripts/       label generator, evaluation runner
tests/         engine tests and expected results
```

Keep the engine free of browser APIs so the same code runs in Node for the evaluation script.

## Testing

- Test labels are generated by a script (rendered from a template, with one defect per variant) using fictional brands. Never use a real brand's artwork. Generated images are for internal testing and are not committed or shipped. The one exception is the tour's sample label (`src/tour/`), a made-up label the app ships on purpose. The generator draws with bundled open-licence fonts so it gives the same labels on macOS, Windows and Linux.
- Commit the generator, the expected-results file and a written test procedure.
- `npm run evaluate` runs the engine over the generated set and prints accuracy and timing.
- The key measure: no known-bad label may ever come out as Ready to Approve. Extra Needs Review results are acceptable.

## Screens

Three screens, all in the approved mockup ("Label Verification Review Mockup"): intake, review in compact mode (about 440 px wide, image on top, one row per field with one row expanded), and review in full mode (image left, rows right, plus a table of what the app read and its confidence). One responsive layout, two sizes. Status uses color, border style and symbol together: solid green check for Match, dashed amber question mark for Check, thick red cross for Mismatch, gray dash for not required. A dotted connector links the focused row to its box on the label. Use Atkinson Hyperlegible, self-hosted. The mockup loads fonts from Google for convenience only. The real app must not.
